# StepBeat Go

Android-приложение: вводишь маршрут, выбираешь музыкальный темп (жанр, свой BPM
или собственный плейлист) — приложение считает, сколько бы занял этот путь,
если идти в такт выбранной музыке.

## Ключевой принцип: без единого API

Приложение не делает ни одного собственного сетевого запроса и не использует
ничьих API-ключей:

- **Маршрут.** Пользователь либо вставляет ссылку на маршрут, скопированную
  из Яндекс.Карт / 2ГИС / Google Карт (координаты вытаскиваются локальным
  regex-парсером из текста ссылки — `util/RouteLinkParser.kt`), либо просто
  вписывает время, которое показали Карты. Кнопка «Открыть в Картах» строит
  deep link и передаёт управление установленному приложению карт —
  `util/MapsAppLauncher.kt`.
- **Темп конкретного трека.** Пользователь сам добавляет треки в плейлист;
  кнопка «Узнать темп» открывает обычный веб-поиск во встроенной вкладке
  (Custom Tabs) с запросом вида `Артист - Название bpm` —
  `util/TempoSearchLauncher.kt`. Число пользователь читает и вписывает сам,
  никакого скрейпинга или парсинга результатов поиска нет.
- **Музыка не проигрывается.** Есть только опциональный синтезированный
  клик-трек (`util/MetronomeEngine.kt`, генерируется на лету через
  `AudioTrack`) как аналог метронома для ходьбы — никаких аудиофайлов,
  лицензий или стриминговых интеграций.

Из-за этого в манифесте нет `INTERNET` permission — приложение физически не
может тайно ничего отправить.

## Формула расчёта

Базовая идея — не считать через длину шага и физическое расстояние, а
масштабировать «время пешком обычным шагом» (то, что показывают карты)
отношением темпов:

```
время_под_музыку = базовое_время × (базовый_BPM / BPM_трека)
```

`базовый_BPM` — темп обычной прогулки (~113 шагов/мин по умолчанию,
настраивается в Settings через tap-tempo калибровку — пользователь просто
жмёт кнопку в такт своим шагам). См. `calc/TempoCalculator.kt`.

Для плейлиста с разными по темпу треками используется честная симуляция
(`TempoCalculator.walkWithPlaylist`): каждый трек проигрывается по очереди,
его реальная длительность переводится в «эквивалент базового времени» через
его собственный BPM, и как только накопленный эквивалент покрывает маршрут —
это и есть момент, когда пользователь дошёл (последний трек может доиграть
не полностью).

Если у пользователя есть только ссылка на маршрут (координаты, но не время),
расстояние по прямой (формула гаверсинуса) переводится в такое же базовое
время через константу `BASE_WALK_SPEED_KMH = 5.0`.

## Структура проекта

- `calc/` — вся математика, чистый Kotlin без зависимостей от Android.
- `data/model/GenreCatalog.kt` — статическая таблица жанр → средний BPM (16
  жанров), зашита в приложение, ничего не подгружается.
- `data/db/` — Room: избранные маршруты, история расчётов, сохранённые
  плейлисты. Всё только на устройстве.
- `util/` — SettingsRepository (DataStore: тема, единицы измерения, язык,
  базовый темп, предпочитаемое приложение карт), LocaleHelper (переключение
  языка через AppCompatDelegate), ClipboardHelper, MapsAppLauncher,
  TempoSearchLauncher, MetronomeEngine.
- `ui/theme/` — светлая/тёмная палитра в духе Apple HIG (почти монохром +
  один акцентный цвет), настраивается в Settings (Светлая/Тёмная/Системная).
- `ui/screens/` — Главная → Выбор режима → (Жанр | Плейлист | Свой BPM) →
  Результат, плюс Избранное/История/Настройки/Достижения/Клик-трек.
- `ui/navigation/NavGraph.kt` — Jetpack Navigation Compose + нижняя панель
  навигации.

## Реализованные фичи

Главный расчёт, ссылка/ручной ввод маршрута, deep link в карты, жанры,
кастомный BPM, плейлисты с ручным добавлением темпа через поиск, избранное,
история, достижения (4 штуки, разблокируются по истории), настройки (тема,
единицы, язык, калибровка темпа через tap-tempo, предпочитаемые карты),
клик-трек-метроном, шаринг результата текстом.

**Не реализовано в этом заходе:** домашний экран-виджет (Glance) — решили не
делать вслепую без возможности проверить сборку; иконка приложения — сейчас
плейсхолдер (равнобедренные «эквалайзер-бары»), заменить перед релизом.

## Известные ограничения текущей версии

- **Локализация не до конца прошита.** Ресурсы `values/strings.xml` (EN) и
  `values-ru/strings.xml` подготовлены, но большинство экранов сейчас берут
  текст напрямую из Kotlin-кода на русском, а не через `stringResource(...)`.
  То есть переключение языка в Settings меняет системный `Locale`, но
  реального переключения текста на экранах пока не произойдёт везде — нужно
  пройтись по экранам и заменить хардкод на ссылки на ресурсы.
- **Сборка не проверена в этой среде.** Здесь нет доступа к Android SDK и
  заблокирован сетевой доступ к Google Maven / Maven Central / Gradle
  Distributions, поэтому `./gradlew assembleDebug` не запускался. Код написан
  и вычитан вручную, но первую сборку нужно сделать в Android Studio — она
  сама скачает Android SDK, Gradle 9.1.0 и все зависимости.
- **compileSdk/targetSdk = 36, AGP 9.0.1, Kotlin 2.2.10, Gradle 9.1.0** — если
  на момент открытия проекта вышли более новые стабильные версии, Android
  Studio предложит их сама через Upgrade Assistant.

## Как открыть

1. Android Studio (актуальная версия, поддерживающая AGP 9.x).
2. Open → выбрать папку репозитория.
3. Дождаться Gradle Sync (первая синхронизация скачает Gradle 9.1.0, AGP,
   Kotlin и все зависимости — нужен интернет).
4. Run на эмуляторе или устройстве (minSdk 26 / Android 8.0+).
